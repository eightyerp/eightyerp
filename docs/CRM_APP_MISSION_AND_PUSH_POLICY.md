# EIGHTY CRM 앱 — 임무 및 PUSH 정책

## 1. 최상위 임무

EIGHTY CRM의 목적은 ERP 기능을 모바일에 복제하는 것이 아니다.

직원이 휴대폰에서 고객을 놓치지 않고, 빠르게 연락하고, 상담기록과 다음 행동을 남기고, 견적·계약까지 이어가게 만드는 직원용 영업 실행 앱을 만든다.

우선순위는 항상 다음 순서를 따른다.

1. 직원 사용성
2. 고객 누락 방지
3. 속도
4. 다음 행동 관리
5. 견적·계약 전환
6. Push/자동화
7. 부가기능

회계·정산·복잡한 지출·관리자 기능을 CRM에 과도하게 넣지 않는다.

---

## 2. 앱 구조 원칙

- ERP와 CRM은 같은 Supabase 고객/직원/상담/일정/견적/계약/수금 데이터를 사용한다.
- CRM은 `/crm` 독립 App Shell + PWA를 우선한다.
- 모바일 고객목록은 카드형을 기본으로 한다.
- 고객카드에는 접수일과 D+ 경과기간을 표시한다.
- 고객목록과 모바일 파이프라인에는 접수기간 조회를 제공한다.
- 고객 개인정보를 Service Worker 캐시에 저장하지 않는다.
- 직원은 본인 담당 고객 중심, 관리자는 전체 고객을 본다.

---

## 3. PUSH의 목적

Push는 알림 개수를 늘리는 기능이 아니다.

다음 3가지를 위해서만 사용한다.

1. 새 고객을 놓치지 않게 한다.
2. 약속한 연락·예약을 놓치지 않게 한다.
3. 진행 중 고객이 장기간 방치되는 것을 막는다.

알림 피로를 막기 위해 동일 상황에서 반복 발송하지 않는다.

---

## 4. 필수 PUSH 정책

### A. 회사 신규고객 배분 PUSH

관리자/회사에서 고객 담당자를 배정하거나 변경하면 새 담당 직원에게 즉시 1회 Push한다.

예시:

- 제목: `새 고객이 배분되었습니다`
- 내용: 고객명 / 상담유형 / 현장·주소 요약
- 클릭: `/crm/customers/{customerId}`

규칙:

- 동일 담당자 유지 시 중복 Push 금지
- 담당자 변경 시 새 담당자에게 Push
- 담당자 미지정 상태는 직원 Push 대상 아님
- 잠금화면 개인정보는 최소화

추가 권장:

- 배분 후 30분 이내 첫 연락 기록이 없으면 `아직 첫 연락이 없습니다` Push 1회
- 첫 연락 기록이 생기면 해당 미연락 조건 자동 해제

---

### B. 일정등록 고객 PUSH

전화상담, 방문상담, 실측, 계약상담, 재연락, 해피콜 등 고객 일정에 대해 담당 직원에게 알림한다.

기본:

- 일정 1시간 전 Push 1회
- 일정 변경 시 기존 알림 기준 무효화 후 새 시간 기준으로 재생성
- 일정 취소/완료 시 예정 Push 해제

예시:

- 제목: `1시간 후 고객 일정`
- 내용: `김영희 고객 · 실측 14:00`
- 클릭: 고객 상세 또는 해당 일정

---

### C. 일정 미처리 / 미연락 PUSH

예정 시각이 지났는데 일정이 완료·취소·재예약되지 않았다면 기본 +30분 후 1회 Push한다.

예시:

- 제목: `고객 연락 확인`
- 내용: `예정 시간이 30분 이상 지났습니다. 처리 또는 재예약해 주세요.`

규칙:

- 완료 시 해제
- 취소 시 해제
- 재예약 시 이전 일정의 미처리 Push 해제
- 동일 일정에서 반복 Push 금지

---

### D. 장기간 방치 고객 PUSH

진행 중 고객이 마지막 유효 활동 이후 장기간 다음 행동 없이 방치되면 담당자에게 알림한다.

초기 권장 기준:

- 3일: 담당 직원에게 1차 Push
- 7일: 담당 직원에게 2차 Push + 관리자/팀장 화면에 장기방치 표시
- 14일: 추가 반복 Push보다 CRM Home/관리자 ERP에서 `장기방치` 강한 경고로 유지

대상 상태 예:

- 신규
- 미연락
- 1차 연락완료
- 상담중
- 방문예약
- 실측예약
- 견적작성중
- 견적제출
- 계약협의

제외 기본:

- 완료
- 취소
- 시공중
- 계약완료 이후 정상 진행 고객
- 명시적으로 보류 처리하면서 보류기한/다음 확인일이 있는 고객

방치 판정은 단순 `created_at`이 아니라 가능한 경우 다음을 우선한다.

1. 최근 상담/활동 시각
2. 다음 연락 일정 존재 여부
3. 예약 일정 존재 여부
4. 고객 현재 상태
5. 마지막 견적/후속 행동

상담·연락·재예약·상태변경이 발생하면 방치 타이머를 재계산한다.

## 5. 추가로 반드시 검토할 누락 방지 기능

### A. 다음 행동 없음

진행 중 고객인데 `다음 연락`, `예약 일정`, `견적 후속`, `계약 확인` 등 Next Action이 하나도 없으면 CRM Home에 별도 노출한다.

- `다음 행동 없음`
- Push는 즉시 남발하지 말고, 24시간 이상 Next Action 없이 유지될 때 1회 알림을 검토한다.

### B. 미배정 신규문의 관리자 알림

신규 문의가 들어왔는데 담당자가 지정되지 않으면 일반 직원이 아니라 관리자/배분 담당자에게 알림한다.

- 목표: 문의 자체가 배분되지 않고 방치되는 것을 방지

### C. 일정 변경/취소 알림

사무실·관리자가 직원 일정을 변경/취소하면 해당 담당 직원에게 즉시 알림한다.

### D. 견적 후속 알림

P4 이후 적용 검토.

견적 발송 후 일정 기간 고객 반응/상담기록/후속 일정이 없으면 담당 직원에게 후속 확인 알림한다.

초기 권장:

- 견적 발송 후 2영업일 내 후속 행동 없음 → 1회 알림

### E. 계약·수금 알림

P4 이후 적용 검토.

영업직원이 실제로 행동해야 하는 경우만 알림한다.

- 계약 확인 예정일 도래
- 약속된 입금일 경과

회계성 반복 알림으로 CRM을 복잡하게 만들지 않는다.

---

## 6. PUSH 피로 방지 규칙

- 동일 이벤트 dedupe key 필수
- 상태가 해소되면 기존 조건 자동 무효화
- 동일 고객 장기방치 Push를 매일 반복하지 않음
- 비긴급 알림은 기본 조용한 시간 정책 검토: 21:00~08:00 발송 유예
- 직원이 알림을 탭하면 해당 고객/일정으로 바로 이동
- Push 실패·구독 만료 시 자동 비활성화 및 재구독 가능
- 직원별 알림 ON/OFF 가능
- 향후 회사 단위로 임계값(30분/3일/7일 등)을 설정 가능하도록 확장성 확보

---

## 7. CRM Home 우선 경고 순서

1. 신규 배분 · 첫 연락 전
2. 예정시간 경과 미처리
3. 오늘 일정
4. 오늘 연락
5. 다음 행동 없음
6. 3일 이상 장기방치
7. 견적 후속 필요
8. 계약 확인

Push와 CRM Home 경고는 같은 기준 엔진을 사용해야 한다. 서로 다른 판정 로직을 중복 구현하지 않는다.

---

## 8. 성능 원칙

- Push 판정을 위해 매번 전체 고객을 Client로 내려받지 않는다.
- 서버/DB 기준 조건 조회 또는 예약 worker를 사용한다.
- 필요한 컬럼만 조회한다.
- 상태/담당자/시간 컬럼 인덱스를 확인한다.
- 전체 고객 수가 수천~수만 명으로 증가해도 CRM Home과 Push worker가 느려지지 않도록 한다.
- Push worker는 idempotent해야 한다.

## 9. 구현 우선순위

### P1/P2 — 앱 기본 사용성

- PWA 설치
- CRM Home
- 고객카드
- 고객검색
- 접수기간 조회
- D+ 경과기간
- 모바일 파이프라인
- 고객상세

### P3 — 영업 실행

- 전화
- 상담기록
- 다음 연락
- 일정
- Next Action
- 미처리 고객

### P4 — 견적·계약·수금

- 기존 ERP 엔진 재사용

### P5 — Push 활성화

필수 4종:

1. 신규고객 배분
2. 일정 1시간 전
3. 일정 +30분 미처리
4. 장기간 방치 고객

이후 검증 후 추가:

- 배분 후 첫 연락 지연
- 다음 행동 없음
- 미배정 문의 관리자 알림
- 견적 후속
- 계약/약속 수금

---

## 10. Release Gate

운영 활성화 전 반드시 검증한다.

- ESLint PASS
- Production build PASS
- 모바일 360/390/430px QA
- Android Chrome PWA
- iPhone Safari/PWA
- 담당자 권한/RLS
- Push subscription 저장
- 동일 이벤트 중복 방지
- 완료/취소/재예약 해제
- 장기방치 타이머 reset
- 테스트 직원 1~2명 E2E
- 운영 DB migration preflight

운영 DB migration, Secret, Edge Function production 활성화, main merge, Production 공개 반영은 승인 전 실행하지 않는다.

## 11. PM 보고 형식

매 단계마다 반드시 보고한다.

- 현재 작업
- 완료
- QA
- 속도
- 발견 문제
- 다음 작업
- 대표님이 해야 할 일

대표가 해야 할 일이 없으면 `없음`이라고 명시한다.

계획된 다음 작업이 명확하면 매번 질문하지 말고 계속 진행한다.
