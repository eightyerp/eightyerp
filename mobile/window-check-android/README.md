# 에잇티 창호체크 Android

에잇티 직원이 고객 현장의 창호를 위치별로 촬영·점검하고, 담당자 검토를 거친 고객용 PDF 리포트와 견적서를 발송하기 위한 Android 내부 MVP입니다.

## v0.2.0 구현 범위

- 직원명·팀·직급과 고객·현장정보 입력
- 거실, 안방, 작은방, 주방, 발코니 등 복수 점검 위치 등록
- 같은 공간의 여러 창을 `거실창 1`, `거실창 2`처럼 직접 추가
- 위치마다 표준 사진 5장 등록
  - 창호 전체
  - 창틀 모서리
  - 유리면
  - 창틀 하부·레일·배수구
  - 손잡이·잠금장치
- 각 사진을 현장에서 촬영하거나 휴대전화 앨범에서 직접 업로드
- 위치별 추가 증상 사진 등록
  - 결로·복층유리 내부 김서림 의심
  - 외부 누수·벽체 유입 의심
  - 파손·뒤틀림·부식 등 기타 이상
- 위치별 결로, 누수, 외풍, 개폐, 소음, 곰팡이 증상 입력
- 위치별 AI 예비분석 결과와 종합등급 표시
- 고객에게 보일 의견과 사내 메모를 분리한 직원 최종 검토
- 위치별 사진과 점검내용이 포함된 고객용 PDF 리포트 생성
- 휴대전화 공유 메뉴를 이용한 카카오톡·문자·이메일 발송
- 기존 견적서 PDF를 선택해 점검 리포트와 함께 발송
- Google Play 등록 없이 설치 가능한 Debug APK 자동 빌드

## 중요한 제한

현재 `FakeDiagnosisRepository`가 촬영·업무흐름 검증을 위한 예시 판정을 반환합니다. 실제 사진을 판독하는 AI 분석 API는 아직 연결되지 않았습니다. 결로와 누수는 사진만으로 원인을 확정할 수 없으므로, 고객 발송 전에 담당직원이 결과와 문구를 반드시 검토해야 합니다.

현재 점검 데이터와 사진은 앱 실행 중 및 기기 임시영역에만 유지됩니다. ERP 직원 인증, Supabase 비공개 저장, 진단이력 복원, ERP 견적 자동연결은 다음 단계에서 구현합니다.

## 기술 구성

- Kotlin
- Jetpack Compose / Material 3
- Android API 26 이상
- compileSdk / targetSdk 36
- Android Gradle Plugin 8.13.2
- Gradle 8.13
- JDK 17

## Android Studio 실행

1. Android Studio에서 이 폴더를 프로젝트로 엽니다.
2. Android SDK 36을 설치합니다.
3. `app`의 `debug` 변형을 실행합니다.

Debug 패키지는 `com.eighty.windowcheck.internal`입니다.

## APK 자동 생성

GitHub Actions의 `Android Window Check APK` 워크플로를 수동 실행하거나, 이 폴더의 변경을 브랜치에 push하면 `eighty-window-check-internal-apk` 아티팩트가 생성됩니다.

생성 파일:

```text
app/build/outputs/apk/debug/app-debug.apk
```

직원 휴대전화에서 APK를 직접 설치할 때는 해당 브라우저 또는 파일 앱의 `출처를 알 수 없는 앱 설치` 권한을 한 번 허용해야 합니다.
